# Sources for the default pack

Where each part of `defaults/` and each T0 validator comes from, and under which licence.
The pack is generic: it names no real person or organisation, and every example string in
`patterns.yaml` is invented.

## Greek name gazetteer (`terms.yaml`: `given-names-male`, `given-names-female`, `surnames`)

- **Source:** Wikidata, through the public SPARQL endpoint
  `https://query.wikidata.org/sparql`, queried on 14 November 2026.
- **Licence:** Creative Commons CC0 1.0, which covers all structured data in Wikidata.
- **Queries** (each returned the Greek label, `FILTER(LANG(?label) = "el")`):
  - given names in use: `?person wdt:P27 wd:Q41 ; wdt:P735 ?name`, counted per name
    (Greek citizens and their given names);
  - gender: items that are an instance of male given name (`wd:Q12308941`) or female given
    name (`wd:Q11879590`) with a native label (`wdt:P1705`) in Greek, and all male given
    names with a Greek label;
  - surnames: `?person wdt:P27 wd:Q41 ; wdt:P734 ?name`, and items that are an instance of
    family name (`wd:Q101352`) written in the Greek alphabet (`wdt:P282 wd:Q8216`).
- **Selection:** single Greek words only. A given name is kept when at least two Greek
  citizens in Wikidata carry it and its gender is known from the native-label lists, or
  when at least three carry it and it has a Greek masculine ending (and is a known male
  name) or a feminine ending. A surname is kept when it has four letters or more. Result:
  255 male and 205 female given names, 1,605 surnames.
- **Forms:** only the dictionary form is stored. Genitive, accusative, vocative and
  feminine forms are generated by rule in `gateway/app/detect/greek_names.py`, and Greeklish
  spellings come from the ELOT 743 table in `gateway/app/core/textnorm.py`.

## Validators in code (`gateway/app/detect/validators.py`)

Each was checked against a public reference implementation, and the unit tests carry
published valid and invalid values.

| Identifier | Rule | Reference |
| --- | --- | --- |
| AFM | Nine digits; the first eight weighted 256 down to 2, summed, mod 11, mod 10, equal to the ninth; all zeros rejected | Agrees with `stdnum.gr.vat` of python-stdnum (LGPL) on 200,000 random numbers. Test values: 094014201, 094259216 (valid), 123456781 (invalid) |
| AMKA | Eleven digits; the first six a DDMMYY date; Luhn check over all eleven | Agrees with `stdnum.gr.amka` on 300,000 random numbers. Test values: 01013099997 (valid), 01013099999 (invalid) |
| IBAN | Country length from the SWIFT IBAN registry; ISO 13616 check, mod 97-10 of ISO 7064; Greek IBANs are `GR` plus 25 digits | Lengths and results agree with `stdnum.iban`. Test value: GR16 0110 1250 0000 0001 2300 695, the registry's example for Greece |
| Payment card | Issuer prefix and length (Visa, Mastercard, American Express, Diners, Discover, JCB, UnionPay, Maestro) and the Luhn check of ISO/IEC 7812 | Published test card numbers (Stripe and PayPal testing documentation) |
| Phone | Greek and international numbers, validated against numbering plans | Google's libphonenumber through the `phonenumbers` package (Apache 2.0) |

### Greek identity card numbers

- **Older cards.** One Greek letter and six digits, or two letters whose capitals exist in
  both the Greek and the Latin alphabet (ΑΒΕΖΗΙΚΜΝΟΡΤΥΧ) and six digits. Source: Microsoft
  Purview, "Greece national ID card entity definition"
  (`https://learn.microsoft.com/en-us/purview/sit-defn-greece-national-id-card`). There is
  no check digit.
- **Current cards**, issued since 25 September 2023 (EU PRADO document GRC-BO-02001) under
  Regulation (EU) 2019/1157, carry a machine-readable zone. ICAO Doc 9303 gives a card of
  this size a document number of nine characters. The pattern used here is two Latin
  capital letters followed by seven digits. **We found no primary source that states the
  split between letters and digits**, so this is recorded as an assumption, and the
  recogniser reports such a number only next to a word like "ταυτότητα", "ΑΔΤ" or
  "identity card".
- **Personal number.** Twelve characters, at least nine of them digits (law 4727/2020):
  a three-character prefix followed by the holder's AFM, as the Ministry of Digital
  Governance presented it. It is recognised when the last nine digits pass the AFM check,
  and reported as an AFM.

## Provider patterns (`patterns.yaml`)

Written for this project from the key and token formats the providers document. The open
source gitleaks rule set (MIT licence) describes the same formats and is a useful second
reference; no rule text was copied from it. Each pattern is verified only by its unit
test, against the invented strings in the file: none was tried against a live credential.

| Group | Formats | Documentation |
| --- | --- | --- |
| `cloud` | AWS access key IDs (`AKIA`, `ASIA` and related prefixes) and secret keys; Google API keys (`AIza`), OAuth client secrets and access tokens, service-account key files; Azure storage keys, client secrets and SAS signatures; DigitalOcean, Alibaba Cloud and Heroku tokens | AWS IAM user guide, "IAM identifiers"; Google Cloud, "Manage API keys"; Microsoft Learn, "Configure Azure Storage connection strings" |
| `code-hosting` | GitHub tokens (`ghp_`, `gho_`, `ghu_`, `ghs_`, `ghr_`, `github_pat_`); GitLab tokens (`glpat-` and related); Bitbucket and Atlassian tokens; npm, PyPI and Docker Hub tokens | GitHub blog, "Behind GitHub's new authentication token formats" (April 2021); GitLab docs, "Token overview"; GitHub blog, "Announcing npm's new access token format" (September 2021); PyPI help, "API tokens" |
| `payment` | Stripe secret and restricted keys and webhook secrets; PayPal Braintree, Square and Shopify access tokens | Stripe docs, "API keys"; Shopify docs, "Access token types" |
| `ai-providers` | OpenAI, Anthropic, Hugging Face, Groq, Replicate, Perplexity and xAI API keys | Each provider's API-key page; Hugging Face docs, "User access tokens" |
| `messaging` | Slack tokens and webhooks; Discord webhooks; Telegram bot tokens; Twilio, SendGrid, Mailgun and Mailchimp keys | Slack docs, "Token types"; Discord developer docs, "Webhook"; Telegram, "Bot API: authorizing your bot"; Twilio docs, "API keys" |
| `tokens` | JSON Web Tokens; bearer and basic authorisation headers | RFC 7519; RFC 6750; RFC 7617 |
| `private-keys` | PEM private key blocks; PuTTY key files | RFC 7468 |
| `connection-strings` | Database URLs and other URLs with a password; JDBC and ADO.NET strings | RFC 3986, section 3.2.1 |

The documentation titles above were written from knowledge of those pages; they were not
all opened again while the file was written.
