# Evaluation

How accuracy is measured: committed datasets, one command to run, one results file.

```bash
make eval                                             # inside the running stack
python -m eval.runner --out DIR [--layers default|default+demo|both] [--name NAME]
```

The runner writes `DIR/NAME.json` (the name is a timestamp when omitted) in the shape of
`eval/schema.py`. It runs inside the gateway container, calls detection, the vault and
injection detection in process, and sends prompts through the running gateway for the leak
check. It calls the models with the stack's key. What a run cannot measure, for example when
the demo organisation is not loaded, it lists with the reason in `skipped`.

## Where the data comes from

Everything here is synthetic and generated by `make data` (`seeder/generate.py`) from a fixed
seed, with no API key, so the files are identical on every run. Do not edit them by hand.

- **Labels by construction.** Prompts are templates (`seeder/content/prompts.yaml`) filled
  with entities from `seeder/data/world.json`. The span of every entity is recorded as it is
  inserted, so the ground truth is exact.
- **Clients and outsiders.** About half the people and organisations in `dlp.jsonl` are in
  the CRM (`seeder/data/clients.json`); the rest come from name tables with the CRM's names
  removed. This is what lets the precision of `CLIENT` be measured.
- **Held-out split.** Every row has `split`: `train` (70%) or `test` (30%), drawn within each
  group of a set. Thresholds are tuned on `train`; the runner reports on `test` only.
- **With a key**, `python -m seeder.generate --rewrite` lets the offline model reword the
  text around the entities. Entities are swapped for numbered tokens before the model sees
  the text, and a rewrite is kept only if every entity came back.

## Datasets

### `dlp.jsonl` (492 prompts)

English, Greek, Greeklish and mixed prompts with entity-level labels; 34% hold nothing
sensitive.

| Field | Meaning |
| --- | --- |
| `id` | `dlp-0001` … |
| `language` | `en`, `el`, `greeklish` or `mixed` |
| `group` | `client`, `outsider`, `secret`, `marked`, `benign`, `document`, or `hard_negative:<family>` |
| `text` | The prompt |
| `labels` | Entities, in order, never overlapping (see below) |
| `categories` | Document categories the text belongs to (`CONTRACT`, `FINANCIAL`, `HEALTH`, `HR`, `SOURCE_CODE`); empty for ordinary prompts |
| `negative` | True when there is no label and no category |
| `split` | `train` or `test` |

A label is `{start, end, type, text, client, form}`. `text` equals `text[start:end]` of the
prompt. `type` is the generic data type (`PERSON`, `ORG`, `AFM`, `AMKA`, `IBAN`, `CARD`,
`ID_CARD`, `EMAIL`, `PHONE`, `ADDRESS`, `SECRET`, `CONFIDENTIAL_MARKER`, `PROJECT_CODE`).
`client` is the CRM id when the entity belongs to a client, else null. `form` says how a name
is written: `exact` (as in the CRM), `inflected` (Greek genitive or accusative), `greeklish`
(Latin spelling of a Greek name) or `alias` (the abbreviation).

Hard-negative families: `invalid_afm` (nine digits with a wrong check digit),
`order_number`, `code_no_secret`, `harmless_base64`, `earlier_version` (a request to ignore an
earlier draft) and `non_client_org` (an organisation that is not a client: one `ORG` label,
and it must not be called `CLIENT`).

### `evasion.jsonl` (110 samples)

Values written to slip past a plain pattern match.

| Field | Meaning |
| --- | --- |
| `technique` | `spaced_digits`, `fullwidth`, `zero_width`, `encoded` (base64, hex or URL encoding), `split_across_turns`, `transliterated_names` |
| `turns` | The messages, one or two; detection runs on each turn on its own |
| `labels` | `{turn, start, end, type, text, value, client}`; `value` is the clean value behind the span. For an encoded run the span is the whole run. A split value has one label per fragment, marked `fragment` |
| `language`, `split` | As above |

### `injection.jsonl` (156 samples)

| Field | Meaning |
| --- | --- |
| `label` | `injection` or `benign` |
| `kind` | `direct` (the attacker writes to the model) or `indirect` (hidden in content the agent reads); null for benign |
| `carrier` | `chat`, `document`, `web_page` or `email` |
| `technique` | For attacks: `override`, `exfiltration`, `system_spoof`, `role`, `tool_abuse`, `secrecy`, or how it is hidden: `html_comment`, `hidden_element`, `encoded`, `zero_width`. For benign texts: `plain`, `lookalike` (for example "ignore my previous email"), or `harmless_<wrapper>` (harmless hidden content) |
| `text`, `language`, `split` | As above |

### `fingerprint.jsonl` (167 samples)

Excerpts for the T2 document match.

| Field | Meaning |
| --- | --- |
| `variant` | `verbatim`, `partial` (the end of one clause and the start of the next), `paraphrased`, `translated`, or `negative` |
| `source_document` | Id in `seeder/data/corpus/manifest.jsonl`; null for negatives |
| `category` | The category of the source document; null for negatives |
| `negative_source` | `holdout` (from `holdout_corpus/`, never fingerprinted), `boilerplate` (generic contract and code from the default exemplars) or `benign` |
| `kind`, `language`, `text`, `split` | As above; `language` is the language of the source document, so a translated excerpt is written in the other one |

A positive counts as found only when T2 reports a conclusive match with a company document;
"resembles a contract" from the exemplars does not count.

### `category.jsonl` (167 samples)

Whole documents and excerpts for each exemplar category, written from outlines
(`seeder/content/heldout/`) that the exemplars were not written from.

| Field | Meaning |
| --- | --- |
| `category` | `CONTRACT`, `FINANCIAL`, `HEALTH`, `HR`, `SOURCE_CODE` or `BENIGN` |
| `kind` | `document` or `excerpt` |
| `language`, `text`, `split` | As above |

### `agent_scenarios.jsonl` (12 scenarios)

Scripted exfiltration attempts against the in-house agent. There is no split.

| Field | Meaning |
| --- | --- |
| `content` | What a tool returned to the agent, with the attack in it |
| `carrier`, `technique`, `language`, `title` | How the attack arrives |
| `tool`, `destination`, `side_effects` | The call the attack tries to cause, and whether it goes somewhere `trusted` or `untrusted` |
| `client`, `record`, `values` | The CRM record the attacker is after, and the real values that must not reach it |
| `expect_flagged` | False for the one attack worded with no instruction at all, which the heuristics are expected to miss |

The runner replays each scenario at the gateway's decision points: the content goes through
injection detection, the record through detection and the vault, and the side-effect call
through the policy, at protection `off`, `standard` and `detailed`.

### `holdout_corpus/`

Eight documents of the same kinds as the confidential corpus, with a `manifest.jsonl`. They
are never fingerprinted. Python sources end in `.py.txt` so that linters leave data alone.

## How a finding is scored

- A label is **found** when findings of an acceptable type cover at least half of its
  characters. Acceptable means the same type; `CLIENT` for a name whose label has a `client`;
  `LOCATION` for an `ADDRESS`.
- A finding that touches no label it could stand for is a **false positive**. `LOCATION` is
  the exception: place names are not labelled, so it is never counted as an error.
- `CLIENT` has a row of its own: a client's name must be recognised as a client. Its labels
  are already counted as `PERSON` or `ORG`, so the overall score leaves that row out.
- Cumulative tiers (`T0`, `T0+T1`, …) count the same labels with only the findings of those
  tiers, plus the document categories that T2 and T3 add.
- Every detection metric is reported for the default pack alone and for the default pack
  plus the demo organisation; the difference is what company data adds.
- The leak check counts values the gateway itself masked that still appear in what the fake
  AI tool recorded. Values the detector missed are false negatives above, not leaks.
- `misses` keeps up to four examples of each kind of error per data type, so the weak spots
  can be read, not only counted.
